# KYOENC3 勝敗証明DAG

`KYOENC3` は、共円ゲームの空盤からの勝敗を局所条件だけで確認できるバイナリ証明形式です。

C++生成器は探索結果から必要な局面だけを取り出します。Rust検証器は探索をやり直さず、各ノードの関係とゲーム規則を独立に再計算します。

## 検証コマンド

```bash
cargo run --release --bin kyouen-cert-verify -- /path/to/board.cert
```

成功時は `CERTIFICATE VALID` と、盤面サイズ、ノード数、根の勝敗を出力します。

## ヘッダー

40バイト、リトルエンディアンです。

| オフセット | 長さ | 内容 |
|---:|---:|---|
| 0 | 8 | magic。先頭7バイトが `KYOENC3` |
| 8 | 4 | version。現在は3 |
| 12 | 4 | 盤面サイズ `N` |
| 16 | 8 | ノード数 |
| 24 | 8 | 根局面の下位64ビット |
| 32 | 4 | 根局面の上位32ビット |
| 36 | 4 | 禁止四つ組数 |

分類証明の根は空盤です。

## ノード

各ノードは16バイトです。

| オフセット | 長さ | 内容 |
|---:|---:|---|
| 0 | 8 | 盤面の下位64ビット |
| 8 | 4 | 盤面の上位32ビット |
| 12 | 1 | 結果。1=`LOSS`、2=`WIN` |
| 13 | 1 | `WIN`の証人手。`LOSS`では255 |
| 14 | 1 | rank。`N*N - 石数` |
| 15 | 1 | 予約。0でなければならない |

盤面は8つの回転・反転のうち、ビット集合として最小の正規形で保存します。

## 局所証明条件

### WINノード

証人手が合法であり、その手を打って正規化した子局面が証明書内に存在し、次を満たす必要があります。

- 子は `LOSS`
- 子のrankは親より小さい

### LOSSノード

全合法手について、回転・反転で重複する子をまとめた各子局面が証明書内に存在し、次を満たす必要があります。

- 子は `WIN`
- 子のrankは親より小さい

合法手がない `LOSS` は終端ノードです。

rankが手ごとに必ず減るため、循環した偽証明は作れません。

## Rust検証器が再計算するもの

Rust側は証明書に保存された次の情報をそのまま信用しません。

- 禁止四つ組数
- 各盤面が共円・共線4点を含まないこと
- 合法手集合
- 8つの回転・反転
- 正規形
- rank
- WIN証人手の合法性
- LOSSノードの全合法子

共円判定には、C++生成器の4×4行列式とは異なる、1点を原点へ平行移動した3×3行列式を使います。

## 現在のCI

GitHub Actionsでは1×1〜6×6について、毎回次を行います。

1. C++生成器で証明書を新規生成
2. 既存C++チェッカーで検証
3. 独立Rustチェッカーで同じ証明書を検証

大きな既存証明書にも同じRustコマンドを適用できます。ただし証明書全体をメモリへ読み込むため、非常に大きな9×9証明書では別途ストリーミング化が必要になる場合があります。
