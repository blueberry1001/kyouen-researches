# kyouen-verifier

共円ゲーム用の、読みやすさと独立性を優先したRust参照実装です。

## 目的

10×10の高速C++探索器をそのまま移植したものではありません。

高速版は、石を置くたびに合法手集合を差分更新します。Rust版は逆に、各盤面の石を3個ずつ列挙し、禁止点を毎回ゼロから再構成します。また、共円判定も高速版の4×4行列式ではなく、1点を原点へ移した3×3行列式を使います。

同じ設計上の誤りを共有しにくいため、次の用途に向いています。

- 1×1〜小さな盤の完全探索
- 10×10探索から抜き出した浅い・軽い局面の照合
- 共円判定、合法手判定、盤面対称性の単体検査
- 10×10のCSV証拠一式の構造監査
- C++版との局面単位の差分検査

単純な `HashMap<u128, Outcome>` を使うため、10×10全体をこの実装だけで再探索するのは現実的ではありません。

## ゲーム規則

正方格子点へ交互に石を置きます。既に置かれた3点と合わせて、同一円周上または同一直線上に4点が並ぶ点には置けません。合法手がない手番のプレイヤーが負けです。

座標は左上を `(0,0)` とする0始まりです。点番号は `id = y * N + x` です。

## ビルド

```bash
cargo build --release
cargo test --release
```

外部クレートは使っていません。

## 自己検査

```bash
cargo run --release -- self-test
```

次を確認します。

- 単位正方形の4頂点が禁止四つ組になる
- 同一直線上の4点が禁止四つ組になる
- 3頂点が置かれた正方形の第4頂点が合法手から除かれる
- 1×1、2×2、3×3、4×4の既知結果

埋め込んだ既知結果は次のとおりです。

| 盤 | 空盤の手番 | 先手勝ちになる初手数 |
|---|---|---:|
| 1×1 | WIN | 1 |
| 2×2 | WIN | 4 |
| 3×3 | WIN | 9 |
| 4×4 | LOSS | 0 |

## 盤面を解く

空の4×4盤：

```bash
cargo run --release -- solve --size 4
```

点番号で盤面を指定：

```bash
cargo run --release -- solve --size 5 --ids 0,1,5
```

座標で指定：

```bash
cargo run --release -- solve --size 5 --coords '0,0;1,0;0,1'
```

探索量を制限する場合：

```bash
cargo run --release -- solve --size 7 --coords '0,0;3,3' --node-limit 1000000
```

出力の `outcome` は、**次に打つ側**から見た勝敗です。

## 全初手を分類する

小盤面向けです。

```bash
cargo run --release -- classify-first --size 5 > first-moves-5x5.csv
```

## C++版と差分検査する

C++照会器をビルドします。

```bash
g++ -std=c++20 -O2 -Wall -Wextra -pedantic \
  ../../cpp/tools/kyouen_query.cpp -o /tmp/kyouen-query
```

4×4では勝敗と双方の勝ち手まで照合できます。

```bash
cargo run --release --bin kyouen-cross-check -- \
  --cpp /tmp/kyouen-query \
  --size 4 \
  --samples 40 \
  --seed 20260801 \
  --max-stones 8 \
  --solve-max-size 4
```

10×10では巨大探索を再実行せず、合法手・禁止点・8対称・正規形・禁止四つ組数を照合します。

```bash
cargo run --release --bin kyouen-cross-check -- \
  --cpp /tmp/kyouen-query \
  --size 10 \
  --samples 100 \
  --seed 20260802 \
  --max-stones 12 \
  --solve-max-size 0
```

詳細は [`CROSS_CHECK.md`](CROSS_CHECK.md) を参照してください。

## 10×10証拠CSVを監査する

証拠一式を展開したディレクトリを渡します。

```bash
cargo run --release -- audit-evidence /path/to/evidence
```

監査内容：

- 15代表初手が重複なく記録されているか
- 100初手が全て一度ずつ記録され、全て `LOSS` か
- 初手・代表初手・応手の回転反転関係が一致するか
- 各98分枝CSVが、占有済み2点以外の全点をちょうど一度含むか
- 対角線対称の53代表CSVが、転置軌道をちょうど一度ずつ含むか
- 全分枝の記録結果が `WIN` か
- 点番号、座標、`state` 文字列が一致するか

注意：現在のCSVは巨大な勝敗証明書そのものではなく、探索結果の集計です。この監査はCSVの完全性・整合性を確認しますが、各 `WIN` を再帰的に証明し直すものではありません。完全な独立検証には、今後C++探索器から各WIN局面の勝ち手と各LOSS局面の全子局面を含む証明DAGを出力する必要があります。

## 実装上の独立性

| 項目 | 高速C++版 | Rust参照版 |
|---|---|---|
| 合法手 | 直前の合法手集合から差分更新 | 盤面から毎回再構成 |
| 共円判定 | 4×4行列式 | 平行移動後の3×3行列式 |
| メモ表 | 深さ別の圧縮順位表 | 標準HashMap |
| 盤面順位 | 組合せ順位 | u128ビット集合そのもの |
| 主目的 | 10×10巨大探索 | 小盤・抜き取り独立検証 |

## 次の拡張

10×10の結論を探索器から独立に検証するには、証明DAG形式を追加するのが次の段階です。

各ノードに次を保存します。

- 盤面
- 判定 `WIN` / `LOSS`
- `WIN` なら、`LOSS` へ移る合法手1個
- `LOSS` なら、全合法手と対応する `WIN` 子ノード

Rust側は探索をせず、この局所条件と共円規則だけを検査できます。
