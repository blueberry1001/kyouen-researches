## 観察

1. **s5 は 200k ではほぼ解けないが、10M なら全件閉じる。**
   最小 130,540 nodes、最大 5,677,449 nodes。「200k では abort、
   5M なら大半が閉じる」という分布になっている。
2. **node 数が budget に対して単調かつ安定**であるのは、
   row 間の memo 混入が修正されている証拠（修正前は
   同じ局面が 8,588 nodes と 1 node の両方で報告されていた）。
3. **WIN と LOSS がほぼ半々**（12 / 11）。したがって s5 局面は
   「片方に偏った層」ではなく、両方向の証明が均衡している層。
4. **legal 数の相関は弱そう**。legal=64 の 2 局面は 130k〜177k で
   最小側、legal=72 の多数は 2M〜5.7M。legal が大きいほど
   難しいという単純な関係ではない。

## 注意（外挿しない）

**この node 数から 11x11 全体の解決時間を線形外挿してはいけない。**
s5 局面が解けることと、中央 1 石局面や 20 返信の二石局面が
解けることは別問題である。実際 `--exact-budget=200k` のままでは
s5 の 23 件中 22 件が abort する。

## Phase 4 への示唆

s5 の difficulty は s6 より桁違いに高い（s6 は 200k で大半閉じている）。
**単一の global exact budget では、s6 に無駄な予算を与えてしまうか、
s5 を abort させるかのどちらかで不正になる。** stone count 別 budget の導入が妥当。
