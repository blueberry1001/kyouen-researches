# Round3 (push2): B501–B502 — n=5 の p_rand 完全 DP の独立再計算

対象: `research/hypothesis-bank-round2-2026-09-27.md` §51 の B501・B502 のみ。
スクリプト: `research/verification/scripts/round3_b501_pgrand_n5b.py`（本 push で新規）
データ: `research/verification/round3_b501_pgrand_n5b.json`

定義（変更なし）: `p_rand(terminal)=0`、`p_rand(S)=(1/|L|)·Σ_{u∈L}(1−p_rand(S∪{u}))`、
L は合法手全体的一様。全称は「空盤から到達可能な安全局面すべて」。
算術: **有理数のみ・浮動小数なし**（層ごとの共通分母 + 多倍長整数 + 層の gcd で既約化）。

## 0. 作業指示の前提の訂正（重要）

指示書は「先行ワーカーは n=5 の DP を**完走していない**」と述べたが、
`round3_b501_pgrand_n5.json` の `n5` 節は**すでに完全**だった
（`level_sizes` は k=0..9 の全 10 層、Σ=151,394、`edge_total`=885,065、
`P_max`=2383/3360、`P_gt_2_3`=36、`P_gt_3_4`=0）。つまり DP 自体はある環境で完走済みで、
前回個票 `round3-batch-b501-b502.md` もそれに基づいて書かれている。

ただしその json を**この環境で再現できなかった**。原因を特定した:

- `round3_b501_pgrand_n5.py` の `popcount()`（57-64 行）は
  `v = v >> np.uint16(8)` で dtype を昇格させるため `while v.dtype.itemsize > 1` が
  永久に偽にならず、**無限ループで終了しない**。実測: n=4 の 1 層目から 300 秒以上
  進まなかった（状態数 0→完了せず）。だから「律速-regime」に掉的。
- 本 push ではこれを**整数ビットの恒等式**に置き換えた
  （`exactly3(m)`: `t = m & (m-1)`; `t` に bit が残る ⇔ `t & (t-1) != 0` 、
  popcount は「最下位 set bit を消す」方式）。浮動小数・外部 lib なし。

したがって本 push の成果は「**独立に書き直した実装で n=5 を完走させ、
先行ワーカーの数値が再現できること、および座標付き証人を確定すること**」である。
ラベル・結論は一致するが、`P_max` を達成する局面数の記録誤りを 1 件直した（下 §4）。

## B501 [全称・大胆] 標準盤のP局面のランダム勝率は2/3以下

- 判定: **REFUTED**（前回: PARTIAL → 今回: REFUTED）
- 前回の一手: 「**n=5 の p_rand 完全 DP**（B501/B502 の決着）。P の最大が 0.563 を超えるか、
  2/3 を超えるか。」（`round2-batch-b501.md` L371／`round3-batch-b501-b502.md` L18）
- 今回の範囲: **n=2,3,4,5 の全到達可能安全局面 157,518 個**を完全 DP。
  n=5 単独: **151,394 状態 / 10 層 (k=0..9) / 辺 885,065 / 最大安全サイズ 9**。
  実行時間 n=5 は **9.41 秒**（列挙 5.71 + 求解 3.00、build 0.148）。
  n=4 は 5,811 状態 / 0.45 秒、n=3 は 298、n=2 は 15。**律速なしの完走。**
- 証拠（すべて厳密な整数演算、報告は分数）:
  - n=5 の P 局面 p_rand の**最大は 2383/3360 ≈ 0.70922619047619047619**。
    2/3 = 2240/3360 との差は **+143/3360 > 0**。**束 2/3 は n=5 で破れた。**
  - **反例（証人）**: `occ = 11329`、石数 **k = 5**、**g = 0（P 局面）**、
    座標 (x,y) = **(0,0), (1,1), (0,2), (1,2), (3,2)**（点 id = y·5+x）、
    **|L| = 8**、残り最大手数 max_rem = **3**。
    子 p_rand（8 個、降順）= 1/2, 2/5, 1/3, 1/4, 1/4, 1/4, 1/5, 1/7、
    平均 = **977/420**、よって p_rand = 1 − 977/420 = **2383/3360**。✔
  - 独立再計算: `fractions.Fraction` のメモ化再帰（numpy も層分母も使わない
    **別コードパス**）で、上位 **8 局面すべて**が p_rand 2383/3360・g=0 と一致
    （`independent_recheck.all_match = true`、8/8、計 264 状態）。✔
  - **2/3 を超える P 局面は 36 個**（n=4 の 0 個から増加）、1/2 超は 644 個、
    3/4 超は **0 個**。
  - n≤4 の P 最大は **76/135 ≈ 0.56296…**（n=4, |L|=9, max_rem=3）— 前回の確定値を再現。
  - 残り最大手数 h ごとの P 最大（n=5）:
    | h | 0 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
    |---|---|---|---|---|---|---|---|---|
    | max p_rand | 0 | 0 | **2383/3360** | 212/315 | 12459851/23284800 | 66591319117/112935513600 | 7245096190817424647/14960657835002880000 | 6961357614697273/13451140910592000 |
    h=3 の 2383/3360 のみが 2/3 超。h=4 の 212/315 は 2/3 を 1/315 下回る。h≥5 はさらに下。
    → **違反は h=3 の層にのみ集中**（3 手なら終端 closeness で高値が出る型）。
  - 参考: 5×5 空盤は **g=1（N）**、p_rand = 2098233734897851147/4218230592576000000
    ≈ 0.4974203493…、|L|=25、max_rem=9。N の p_rand 範囲は [1/12, 1]。
- 判定の根拠 / 残った障害:
  - B501 は全称命題（「標準盤の P 局面は全て p_rand≤2/3」）。**1 個の厳密な反例
    （occ=11329, 2383/3360 > 2240/3360）で全称は反証される。** よって PARTIAL を
    通り越えて **REFUTED**。前回 PARTIAL ADOR は「99.911% が 2/3 以下」という
    割合の記述だったが、全称命題の判定は割合では決まらない。
  - 残った障害: ただし「**P の p_rand が 2/3 を超えうる**」こと自体は n=5 で確認。
    未解明は (i) n≥6 で 2/3 超えがさらに増えるか否か、(ii) 3/4 への到達は可能出现か。
    前回個票の次の問い「2/3 超えは h=3 の 36 例に限られるか、n で増えるか」は未答のまま。

## B502 [存在] P局面でランダム勝率3/4を超えられる

- 判定: **INCONCLUSIVE**（前回: INCONCLUSIVE → 今回: INCONCLUSIVE。範囲・母集団は
  n=2..5 の全 157,518 状態、証人は依然としてない）
- 前回の一手: 「n≥5 の P 局面探索」（n≤4 に証人なし、0.563 の壁）
- 今回の範囲: n=2,3,4,5 の**全到達可能安全局面 157,518 個**（n=5 = 151,394、
  n=4 = 5,811、n=3 = 298、n=2 = 15）。n=6 以降は未（完全列挙は本 push の律速外）。
- 証拠:
  - n=5 の P 局面で **p_rand > 3/4 となるものは 0 個**（`P_gt_3_4 = 0`）。n≤4 でも 0 個。
    したがって **n≤5 の全 P 局面で p_rand ≤ 2383/3360 < 3/4**。
  - 余裕は **3/4 − 2383/3360 = 137/3360 ≈ 0.0408**。前回個票の「0.709 から 0.75 まで
    が薄い」と一致——この 137/3360 は今回独立に再計算して確認した。
  - 高値の機構（材料）: 8 個の **異なる値**の p_rand の子（1/2,2/5,1/3,1/4,1/4,1/4,
    1/5,1/7）に手を広げた P 局面が random 勝率を上げる。2383/3360 を達成する 8 局面は
    すべて k=5, |L|=8, max_rem=3 という**単一の型**。n=5 では |L|=8 が上限。
    **n≥6 で |L|≥9 の同型 P 局面があれば 3/4 は射程内**だが，本次未構成。
  - N 側（参考）: n=5 の N の p_rand 最小 **1/12**、最大 1。
- 判定の根拠 / 残った障害:
  - 存在命題なので n≤5 の不発見は反証にならない。**INCONCLUSIVE が正しいラベル。**
  - 残った障害（具体的）: n=6 の P 局面 3/4 超えを実証するには、
    (a) n=6 の |L|≥9・子 p_rand 分散型の P 局面を構成し p_rand>3/4 を厳密に示す、
    もしくは (b) n=6 以上の部分木完全列挙（`round3_b501_pgrand_n5.py --n6 N` の
    サンプリング枝が与える「到達部分木の厳密上界」）が必要。いずれも本 push の
    律速（4 分）外。

### 検算・注記（信頼性）

- **完全性の自己監査**: 列挙は「親が安全 → 生成 → 子の整数安全性を独立再検査してから
  採用」であり、`unsafe_children_dropped = 0`、`generated = 885,065 = edge_total`。
  よって n=5 の母集団 151,394 に取りこぼしはない（`enumeration_audit`）。
- **有理数の一致**: p_rand は層ごとの共通分母（桁数 19/21/20/19/17/14/10/3/1/1）で
  多倍長整数保持。各状態は `[0,1] 範囲アサート通過`。2/3・3/4 との比較は交差積の
  整数演算（`143/3360`, `137/3360`）。**DP 内に浮動小数は 1 つも無い**
  （json の `*_dec` は整数除算による打ち切り表示のみ）。
- **別実装での独立照合**: `fractions.Fraction` 再帰（dict・非 numpy・非層分母）が
  argmax 上位 8 局面すべてで p_rand・g 一致（`all_match=true`）。これは先行ワーカーの
  数値の再現でもある。
- **前個票の記録誤りの訂正 1 件**: 先行 json は `P_max_n_attaining = 16` と記録して
  いたが、本 push の厳密な全走査（Fraction での全層 argmax）では **8**。16 は
  push-1 の `top` 表が argmax を状態ごとに重複計上した数和だったためと見られる。
  結論（P_max=2383/3360、P_gt_2_3=36、P_gt_3_4=0、n_P=40,325、edge_total=885,065、
  level_sizes、per_level_denominator_digits、empty p_rand）はすべて一致・確認済み。
  唯一の差はこの「達成局面数」1 項目のみで、判定には影響しない。
- 既存ファイル（`round3-batch-b501-b502.md`, push-1 の .py/.json, hypothesis-bank,
  PROTOCOL.md 等）は**一切編集していない**。本 push の書出しはこの
  `round3-batch-b501-b502-push2.md` と新規スクリプト・json のみ。
