| budget | 解けた | WIN | LOSS | unknown | total nodes | min | max |

| 2,000,000 | （進行中のため打ち切り） | | | | | | |

in-search の記録と同じ WIN/LOSS 分布が cold replay でも再現した
（1924 / 79）。したがってこの偏りは TT 状態の副作用ではない。

| 層 | root 数 | 全部閉じる budget | 最悪 nodes | 平均 nodes | WIN / LOSS | 偏り |

最悪 nodes は s5 の 5,677,449 から s8 の 67,804 へ、83 分の 1 になった。

## 層ごとの偏りが交互に現れる

| 層 | WIN/LOSS | 方向 |
|---|---|---|
| s6 | 43 / 0 | WIN のみ |
| s7 | 47 / 254 | LOSS 84% |
| s8 | 1,924 / 79 | WIN 96% |

s6 → s7 → s8 で偏りが **WIN → LOSS → WIN** と反転している。
これは「石が増えるたびに結果の傾向が入れ替わる」ことを意味し、
parity 構造（s6 は OR 側、s7 は AND 側、s8 は OR 側）と整合する。
つまり **手番側の max/min 構造が層ごとに偏りを生んでいる**
可能性が高く、**特定の層の偏りがゲーム全体の勝敗を示すわけではない**。

## 現在の bottleneck（更新）

**s5 のみが桁違いに重い。**
他の層（s6 1M、s7 1M、s8 200k）はすべて budget 内で閉じるが、
s5 は 10M が必要。しかも s5 は 23 件しかなくすべて unique なので
再利用の余地もない。

したがって「s5 をどうするか」が単独で残る課題であり、
その他の層はすでに解決済み（軽い）ということになる。

## 次の手への示唆

1. **二石 root の 20 返信を、s6/s7/s8 の gate 付きで再 sweep**。
   s8 が 96% WIN であるなら、二石 root の証明は
   「s8 の大量的な WIN をまとめて得られる」ことで進む可能性がある。
2. **s5 専用にもう一段予算増やす（20M）**して abort をゼロにする。
   bench 上 s5 は 10M で全件閉じているが、center20 sweep では
   s5 の重複がないため 1 回ずつしか解かない。
3. **s5 の 23 件がなぜ重いのか**（層間の比較として）。
   s8 の 11 nodes で解けるような局面が s5 で 5.7M かかるのは
   completion/ban の構造か。D4 軌道の作り方の差を調べる。
