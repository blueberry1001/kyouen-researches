# exact frontier の上層: 構造的な限界の発見

**11x11 の勝敗は UNKNOWN のまま。**
本ファイルは**途中経過**であり、勝敗の断定ではない。

- base commit: `9523906`
- script: `dfpn_record_scan.sh`、`dfpn_legal_bound.py`
- 機械: WSL / g++ -O3 -march=native、16 cores / 19 GB RAM
- memo 2^24、budget 60 s、publish=root、swap 使用 0

## 目的

ordering A/B が dead end になったため、次に「s5 より上の層」を
測る計画だった。二石 root は**両方の子が未解決なら閉じられない**ので、
s7 以降の difficulty が次の bottleneck になりうる。

## 観測 1: 閾値を上げても s7 以上は現れない

s5 の budget を 200,000 に固定して budget を温存し、閾値を進めた結果:

| threshold | s5 handoffs | s6 handoffs | s7 以上 |
|---|---:|---:|---:|
| L72 | 23 | 45 | 0 |
| L76 | 33 | 33 | 0 |
| L80 | 50 | 11 | 0 |
| L84 | 1 | 0 | 0 |
| L88 | 1 | 0 | 0 |

**L84 以降は s5 すら 1 件しか出ない。** s5 の budget を 5,000,000 に
戻すと逆に **全 threshold で s5 が 1 件だけ** になり、上層に到達しない。
これは s5 が budget 内で解けて frontier が空になる一方だと解釈できる。

## 観測 2: 構造的な理由

`dfpn_legal_bound.py` で計算した **合法手数の上限**が答えを規定する。

n=11 は 121 点。k 石置いた局面の合法手数は高々 `121 − k` である
（さらに完成禁止点があればもっと減る）。つまり:

| stones | 合法手数の上限 |
|---|---:|
| 5 | 116 |
| 6 | 115 |
| 7 | **114** |
| 8 | 113 |

**k 石局面を exact handoff できるには L >= 121 − k でなければならない。**
したがって:

- s5 を取り出すには L72 から L80 あたりが自然（多くの s5 がその範囲の legal を持つため）
- s6 を取り出すには L 115 以上
- s7 を取り出すには L 114 以上
- さらに上の層を上げるたびに閾値は 113, 112 ... と狭くなる

**L が高いほど浅い層も同時に handoff 条件を満たす**ため、
「s7 だけを取り出す」ことは原理的にできない。
閾値 1 つのスイッチで層を選別できない。

## 観測 3: L80 の handoff で実際に見えたもの

| threshold | s5 の max legal | s6 の max legal |
|---|---:|---:|
| L76 | 76 | 64 |
| L80 | 80 | 61 |

L を上げると s5 の legal は上限に張り付くが、
**s6 の legal は逆に小さくなる**。つまり s6 は L を上げても
gate を満たさない位置が増えて減る。

## 結論

**「s5 より上」を gate 一つで分離することはできない。**
層を選別するには `--exact-legal` ではなく別の基準が必要
（depth、legal 数そのものではなく残り自由度、
あるいは局面の終盤-ness を表す別指標）。

したがって Phase 9 の「L76, L80 ... をさらに上げる」は、
**s7 以上を専用に pull することはできない**という点で
構造的に不利である。同じ budget を s5/s6 に再投入するだけ。

## 次の手への示唆

1. **層別 gate を導入する**。
   `--exact-legal-by-stones=5:80,6:72,7:64,...` のように
   stone count ごとに閾値を持てば、層を選別できる。
   budget by stones と同じ考え方。
2. **あるいは L120 以上を素朴に試す**。s5/s6 と混ざるだけだが、
   「層を混在させることで budget 配分が改善するか」の実験になる。
3. **legal 数以外の基準**（depth、終盤-ness）を検討する。
