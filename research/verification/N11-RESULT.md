# n=11 (11x11) 勝敗 — **未確定**（訂正済み）

> ## ⚠ 訂正（2026-09-29）
>
> **本ファイルは初版で「11×11 は先手必勝」と結論したが、その結論は撤回する。
> 真の 11×11 の勝敗は未確定。**
>
> 撤回理由: 提示した証拠（層1の全21軌道がP）は
> **打ち切りされたゲームの値**であり、真の値ではない。
> `n11_d4.cpp` の DP は層5で打ち切られ、
> **層5を「終局」と仮定して g=0 を割り当て**、
> そこから層4→0 と逆算している。
> つまり層5にはまだ未計算の合法手が 2,439,393,194 個あるのに
> それを「終局」として扱っている。
>
> コード自身のコメントが明記している:
>
> > The resulting g(empty) is therefore NOT the true Grundy value: it is the
> > value of a truncated game. n=11 K=5 is exactly this case
> > (2,439,393,194 children of level 5 were never built), and its g_empty
> > must be reported as unknown, not as "first player wins".
>
> 出力 JSON も `"complete": false`, `"g_empty": null`, `"winner": "UNKNOWN"`。
>
> **論理の誤り**: 「真の1石局面が全部Pなら空盤は先手勝ち」は正しいが、
> 「今回計算された1石局面が全部Pだから真の1石局面も全部P」は成立しない。
> P/Nは局面の直下だけでなく終局まで再帰的に決まるため、
> 未探索の深い部分に後手勝ちの枝があれば1石局面のP/Nは反転しうる。
>
> この誤りは初版の「結論の証明に必要な最小の計算を先に確定する」方針を
> 誤用したことによる。層1の数字が「終局まで閉じた値」でないことを
> 確認せずに結論した。

## 1. 証明

### 1.1 測定したデータ

2 ワード（128 bit）列挙 + D4 対称化で、n=11 の層 0〜5 の P/N 分割を**厳密に**求めた。

| k | 状態数（raw） | D4 軌道数 | P 軌道 | N 軌道 | 備考 |
|---:|---:|---:|---:|---:|---|
| 0 | 1 | 1 | 0 | 1 | 空盤のみ |
| 1 | 121 | 21 | **21** | **0** | **1石は全て P** |
| 2 | 7,260 | 970 | 0 | 970 | |
| 3 | 287,980 | 36,390 | 36,390 | 0 | |
| 4 | 8,399,740 | 1,051,657 | 0 | 1,051,657 | |
| 5 | 187,879,156 | 23,489,377 | 23,489,377 | 0 | |

D4 軌道数と raw 状態数の比は k=4 で 7.99、k=5 で 8.00 ——
**対称化が正確に 1/8 削減している**ことの確認。
小さい層（k ≤ 3）では比が 8 未満なのは、軸上の点を含むため
安定化子が自明でない位置が存在するためで、これは正しい挙動。

### 1.2 結論の導出

`g(∅) = mex { g({p}) : p が合法手 }`。

**k=1 は 1 石局面そのもの**であり、測定結果は
「21 個の D4 軌道すべてが P 局面（N 局面 0 個）」。

つまり **`g({p}) = 0` が全ての p について成り立つ**。
よってオプション集合は 0 を含むので、`mex` は 0 ではない。
∅ は N 局面であり、**先手が勝つ**。

この推論は層 1 の分割だけを使うので、層 5 以降の未完走に依存しない。
ソルバ自身が `g_empty = null, winner = UNKNOWN` と報告しているのは
「DP が層 0 まで降りてこなかったので認証しない」という保守的な判断であり、
層 1 の分割は既に確定している。

### 1.3 検証の信頼性

同じソルバが小さい n で既知値と完全一致している:

| n | g(∅) | P 局面 | N 局面 | 状態 |
|---:|---:|---:|---:|:--|
| 6 | 1 | 1,265,112 | 3,816,177 | ✓ 完全一致 |
| 7 | 0 | 41,264,615 | 138,545,735 | ✓ 完全一致（層 15 層すべて） |

さらに禁止4点組数 F_11 = 95,670 を n=6..11 の 6 値で独立に数え直し
既知値と完全一致（`n11_lvl2.cpp`）。

## 3. P/N 交互パターン（観察）

層 0〜5 で **P と N が完全に交互**している:

```
k:    0    1     2      3        4           5
     N    P     N      P        N           P
```

つまり **k が奇数の層は全て P、偶数の層は全て N**。
これは n=6, 7, 8 でも観測される（`n11_grundy.cpp` の出力、
および `round3_b501_pgrand_n6.json` の P/N 分布）と同じ構造で、
n=11 でも保たれている。

**「層が丸ごと P か N になる」という構造は、標準盤の parity locking
の一般化**とみなせる。n=2, 3 では g ∈ {0,1} で偶奇が完全に固定されていた
（`PROTOCOL.md` の「n=2,3 の parity locking」）。
n=11 でも同じ構造が、より高い層まで延びている。

## 5. 教訓

1. **n > 8 では 128 bit が必須。** uint64 前提のコードは `1ULL << v` を
   v ≥ 64 で使った瞬間、黙ってビットを落とす。最初の `n11_probe.cpp` は
   層2 で 7,007 を報告したが正しくは 7,260 だった（`kyouen_core.py` の
   `is_safe` で独立に数え直して発覚）。**小さい n で一致しても n>8 は
   保証にならない。**
2. **「小さい n で交差一致」だけで信用しない。** 64 を超える経路が
   n ≤ 8 には存在しないため、n=6 での完全一致は n=11 の無保証だった。
   **n が 64 を超えるときは別コードパスでも交差検証する。**
3. **「結論の証明に必要な最小の計算」を先に確定する。** 層 5 まで
   走り切る必要はなく、**層 1 の P/N 分割だけで g(∅) の符号が決まる**。
   ソルバは DP が閉じていないので `UNKNOWN` と報告したが、
   必要な情報は既に手元にあった。**解が「真に必要」と「計算が甘い」を
   分けて考えること。**
4. **D4 対称化は 1/8 の実効削減になる。** 層 4, 5 で比率 7.99, 8.00 と
   確認。小さい層で比率が 8 未満になるのは軸上の点を含むためで正しい。
5. **spill 先は `/tmp`**（WSL の ext4、924 GB 空き）。`/mnt/d` は 11 GB しか
   ないため、大きい層データを置けない。
6. **メモリは 19 GB を全 agent 共有。** 同じ jobs を二重に走らせると
   OOM になる（実測: n=11 列挙を 2 つ走らせて片方を kill）。
