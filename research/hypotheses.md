## H1: 8石LOSSルートの部分集合に「コア {61,66}」構造がある

- 仮説: 10×10 の 8石LOSSルート `90,61,2,73,69,66,13,91` の LOSS 部分集合のうち、4石以上のものはすべて `{61,66}` を含む。
- 根拠: 4石LOSS 12個のリスト (docs/10X10_FOUR_STONE_SUBSETS_AND_PROOF.md) がすべて `61` と `66` を含むことを目視確認した。
- 検証方法: 全LOSS部分集合リスト (2〜8石) を機械的に抽出し、共通部分集合を計算する。
- 実験結果: 入力状態のままだと 2石{61,66},{90,61} / 3石{90,2,91},{90,73,91} / 4石は全12個が{61,66}を含む / 5石は全11個が{91}を含む / 6石は全3個が{61,66}を含む。しかし D4 正規形に直すと、4石LOSS 12個のうち 2石LOSS の正規形 {0,13},{31,36} を含むのは4個のみ (残り8個はどちらも含まない)。「{61,66} を全4石LOSSが含む」は R の特定座標表示による見かけ。
- 支持/反証/未確定: **反証 (正規形ではコア構造は消える)**

## H2: LOSS 部分集合の層間でコアが切り替わる

- 仮説: 2石LOSS `{61,66}`, `{90,61}` / 3石LOSS `{90,2,91}`, `{90,73,91}` / 4石LOSS はすべて `{61,66}` を含む / 5石LOSS はすべて `91` を含む / 6石LOSS はすべて `{61,66}` を含む。LOSS族の構造が層ごとに不連続に切り替わる。
- 検証方法: 機械的に全層のLOSS集合の包含関係・共通部分を計算 (analyze_subsets.py + 正規形比較)。
- 実験結果: 層ごとの構成は確かに切り替わる (2石2個 → 3石2個 → 4石12個 → 5石11個 → 6石3個)。ただし正規形ベースでは「全層のLOSSに共通の石」は存在せず (2石層の共通部分は空集合)、層間のコアは入力状態の見かけ。
- 支持/反証/未確定: **部分的に反証 (層の非対称性は事実だがコアの切替は座標依存)**

## H3: 3石の探索コストは盤上の構造制約に依存する

- 仮説: 辺・コーナーに集中した3石配置 (構造制約が弱い) ほど探索が重く、中央付近の配置は軽い。
- 検証方法: visited/memo と座標の相関を機械的に解析 (cost_correlation.py)。
- 実験結果: **支持**。log10(visited) vs Σd (危険4点組数合計) は -0.786 の強い負相関。3石の探索コストは「90/91を含む」配置で中央値93M・166M、含まない配置で13M (約33倍差)。ただしこの効果は 4石では消える (-0.045)。合法手数は94-97でほぼ一定で、コスト差を説明できない。
- 支持/反証/未確定: **支持 (3石のみ)**

## H5: 証明書の LOSS/WIN ノード比は盤面サイズと規則的に関係する

- 仮説: 証明書の LOSS ノード割合が n に対して非単調なパターンを持つ。
- 検証方法: KYOENC3 証明書を解析して LOSS/WIN 比、rank 別ノード数を計算 (cert_stats.py, cert_loss_ratio.py)。
- 実験結果: 7×7: 35.4%, 8×8: 34.2%, 9×9: 34.4% でほぼ一定 (3%の範囲内)。証明書の LOSS/WIN 比はサイズに依存しない。さらに、9×9 証明書では石数0〜17の全層で「LOSS=奇数石数, WIN=偶数石数」が完全分離するが、これは root が WIN (0石) で、KYOENC3 の保存規則 (WIN の witness 子 + LOSS の全子を正規化保存) から構造的に必然であり、ゲームの性質ではない。
- 支持/反証/未確定: **反証 (比率は一定、パリティ分離は形式の必然)**

- 仮説: 証明書の末端 (最小 rank) は飽和状態の LOSS で、その親 (WIN) は合法手1個のみ。
