# 発見記録

十分に検証された発見のみを記載する。各項目: 発見内容・なぜ非自明なのか・証拠・再現方法・試した反証・成立範囲・確信度・今後の検証方法。

## F-A: 9×9 の証明書末端は「16石WIN(合法手1) → 17石LOSS(完全飽和)」で閉じる

- 発見: KYOENC3 9×9 証明書の末端層は石数16と17のみで、16石WINノード10個はすべて「合法手が1つだけ」、その唯一の合法手 (= witness) を打つと 17石LOSS ノード(1個)に到達する。17石LOSS ノードは合法手0 = 完全飽和状態。つまり 9×9 には「81点中17石 (21%) でゲームが詰む」盤面が存在する。
- なぜ非自明なのか: ランダムに17石を撒けば残り64点の大半が置けるはずで、21%の石数で「全64点が既存石と共円/共線」になるのは極端に制約が強い状態。また、証明書は石数18以上の層を一切含まない — 証明は「17石以下の構造」だけで空盤面の勝敗を確定している。
- 証拠: `scripts/analysis/cert_terminal.py` — 17石ノードの全64空き点を4点行列式で共円/共線判定し合法手0を確認。16石ノード10個の合法手=1 が witness と一致。
- 再現方法: `python scripts/analysis/cert_terminal.py` (scratch/certs/extracted/kyouen-9x9.cert が必要)
- 試した反証: 16石WINの合法手がwitnessと一致することを確認 (判定実装の正当性も同時に検証)。4点行列式は整数演算で厳密。
- 成立範囲: 9×9 の公開証明書に含まれるノード (証明に使用された状態)。「17石未満で飽和する状態」や「18石以上置ける盤面」の有無は証明書からは判定不能。
- 確信度: 高 (実測・整数演算)
- 今後の検証方法: 9×9 のランダム状態で最小飽和石数をモンテカルロ推定する。

## F-B: results/10x10/*-stone-subsets-of-medium-loss.csv の state 列は「正規化されていない」入力状態

- 発見: `results/10x10/` の 5 つの CSV に載る state 列のうち 196/218 (89.9%) が、C++ ソルバーと同じ D4 変換で求めた正規形と一致しない。例: `[2,61,90]` の正規形は `[9,16,20]`。つまり state 列は探索器の正規化キーではなく、実験時の入力状態そのもの。一方 outcome-cache.json のキーは正規形。
- なぜ非自明なのか: 文書 (docs/10X10_*_SUBSETS_AND_PROOF.md) は状態を「正規化された」ものとして扱う含みがあり、CSV の列に「正規化」の注記はない。既存の「4石LOSSは全て{61,66}を含む」等の観察は正規形では成立しない (4石LOSS 12個中、2石LOSS正規形を含むのは4個のみ)。
- 証拠: `scripts/analysis/cache_core_classify.py` の norm() と CSV との照合: total=218, non-canonical=196。
- 再現方法: `python -c "from scripts.analysis.cache_core_classify import norm; ..."` (スクリプトはワークツリーにあり)
- 試した反証: C++ の tbit 変換 (nx/ny 配列) を直接移植して整数比較で正規形を計算。変換の正しさは 10×10 危険4点組総数 54,441 の照合 (quadruple_stats.py) と 9×9 の 29,152 照合で裏付け済み。
- 成立範囲: results/10x10/ の5CSV (2〜6石)。cache は既に正規形。
- 確信度: 高 (実測)
- 今後の検証方法: 生成時のスクリプト (実験履歴) で state 列の生成経路を確認する。

## F-C: 証明書の LOSS/WIN 比は盤面サイズに依存しない (34〜35%)

- 発見: KYOENC3 証明書の LOSS ノード比率: 7×7=35.4%, 8×8=34.2%, 9×9=34.4%。ノード数が 8×8 と 9×9 で 1.5 倍異なるにもかかわらず比率はほぼ一定。
- なぜ非自明なのか: 証明書のノード分布は盤面ごとに大きく異なる (7×7 のピーク層は石数9、9×9 では石数12) のに、LOSS/WIN 比は安定している。探索戦略・正規化効率の統計的普遍性を示唆する。
- 証拠: `scripts/analysis/cert_loss_ratio.py` の実測。
- 再現方法: `python scripts/analysis/cert_loss_ratio.py`
- 試した反証: 層別の内訳確認 — パリティ分離 (LOSS=奇数/WIN=偶数) は KYOENC3 の保存規則 (WIN の witness 子、LOSS の全子を正規化保存) から構造的に導かれ、ゲームの性質ではないことも確認。
- 成立範囲: 7×7〜9×9 の公開証明書。
- 確信度: 中 (3サイズのみの実測)
- 今後の検証方法: 5×5・6×6 証明書でも同様に確認する (取得済みなので可能)。

## F-D: 3石探索コストと危険4点組数の強い負相関 (r=-0.786) は3石層だけの現象

- 発見: 10×10 の3石26局面で log10(visited) vs Σd (危険4点組数の合計) のピアソン相関 -0.786。90/91 (コーナーとその隣) を含む配置は visited 中央値 93M〜166M、含まない配置は 13M (約33倍差)。合法手数は94-97でほぼ一定なのに visited は65倍差。同じ分析を4石に適用すると相関は -0.045 に消える。
- なぜ非自明なのか: 「合法手が少ない = 探索が軽い」という素朴な予想は成り立たない (合法手数はほぼ一定)。代わりに「危険な4点組が少ない (自由な) 配置ほど探索が重い」= コーナー寄りの配置が LOSS 判定の全探索で最もコストが高い。
- 証拠: `scripts/analysis/cost_correlation.py` (EXACT_INDEPENDENT_SEARCH の visited を使用)。
- 再現方法: `python scripts/analysis/cost_correlation.py`
- 試した反証: 合法手数との相関 (-0.30)、4石での相関 (-0.045) — 3石特有の現象であることを確認。
- 成立範囲: 10×10、3石 (R の部分集合26局面)。
- 確信度: 中 (26局面のみ)
- 今後の検証方法: R 外の3石局面 (ランダムサンプル) で再確認する。

## F-E: 「Σd が小さい = LOSS」は序盤 (2石・3石) だけの傾向で、4石では反転する

- 発見: 10×10 の 8石LOSSルート R 内で、2石ペア28個の LOSS 2個 ({90,61}=3804, {61,66}=4788) は Σd 最小の2つ (3番目は WIN の {73,66}=4894)。3石 LOSS 2個も Σd 最小クラス (5172, 5640)。しかし 4石 (R内全70個) では LOSS 12個の Σd 平均 8733 (範囲 8033-9472) が WIN 58個の平均 8285 (7252-9263) を上回る。つまり「自由度の高い (危険4点組の少ない) 配置ほど負けやすい」のは序盤に限られ、石が増えると「危険な配置ほど負けやすい」に反転する。
- なぜ非自明なのか: 2石・3石の LOSS と 4石の LOSS では「危険4点組の合計」に対する傾向が逆方向。同一のゲーム内で石数によって勝敗の決め手が逆転する。
- 証拠: results/10x10/ の CSV (state, outcome) と scratch/d_per_point.npy の d(p) を結合した集計 (上記コマンド)。
- 再現方法: `python -c "..."` (four-stone-subsets の state 列と d_per_point.npy の合計を LOSS/WIN 別に集計)
- 試した反証: 2石・3石・4石の全層で同じ集計を行い、傾向の反転を確認。
- 成立範囲: 10×10、R の部分集合 (バイアス注意: cache の 4石WIN は 2 個しかなく、R内CSVを使った)。
- 確信度: 中 (R 内のみ)
- 今後の検証方法: R 外のランダム4石で LOSS/WIN を数個ずつ解いて確認する。
